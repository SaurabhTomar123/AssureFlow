# Decisions

Each entry records a deviation from, or a verification of, the v1.4 specification (X-03, X-04).

| ID | Decision | Why | Effect on acceptance |
|---|---|---|---|
| D-01 | Docker image uses Python 3.12 (spec); local development ran on 3.14. | The machine had 3.14 only. | None; CI and Docker target 3.12. |
| D-02 | Switch server pinned to **0.31.0** (`SWITCH_SERVER_VERSION`). The adapter speaks the WebSocket agent protocol (`/agents/{id}/connection/ws`, `scope=all&filter=all`), posts with `POST /agents/{id}/message`, downloads attachments with `GET /agents/{id}/rooms/{room}/media?mxc=` and uploads exports with `POST /agents/{id}/rooms/{room}/media`. SSE is not used. Verified against the 0.31.0 source (`core/switch_core/bridges/agent/api/handlers.py`). | Release docs and source agree; SSE is deprecated. | P0-08/P0-09: the adapter receives every room event (`filter=all`), addressed or not, and acts on workflow events in code. |
| D-03 | Room isolation = Switch room membership **plus** Assure Flow authorization. Authorization reads only `shop_memberships` and `ca_assignments`; the outbox rechecks each room's declared audience (`room_members`) before every send. | Room links and bindings never grant access (spec s.2). | R03/R09/R17 offline tests. |
| D-04 | Each Alembic revision creates exactly its phase's tables from the ORM metadata (tables tagged `info={"phase": ...}`) instead of hand-written DDL. Append-only tables get a trigger that rejects UPDATE/DELETE. | One source of truth for the binding schema; downgrade drops the phase. | Migrations tested up/down/up. |
| D-05 | Outbox delivery is a dedicated, single-threaded dispatcher loop inside the worker (fast lane) rather than one `send_outbox` job row per message. | Strict per-room ordering without lock juggling; no lock held during the network call. | R08/R11 ordering and at-least-once semantics hold. |
| D-06 | Case threading uses explicit case IDs (`INV-0001`) in every message; a reply in a thread whose root is a delivered Assure Flow message is also resolved to its case/RR. | Switch's `POST /message` takes no thread id in 0.31.0; the spec allows case IDs where threading is not equivalent. | None. |
| D-07 | The business-tool surface is an authenticated HTTP tool API (`api/routers/tools.py`): per-agent bearer token + opaque `X-Request-Context` resolved server side, permission = agent tool allow-list ∩ human rights ∩ room scope. A standard MCP wrapper over these routes is deferred. | Time; the authority model (the hard part) is implemented and tested. | Isolation matrix enumerates every route (P5-05). |
| D-08 | Python threads cannot be killed, so `JOB_MAX_DURATION_SECONDS` is enforced by (a) running all CPU work in killable subprocesses with hard timeouts, (b) hard timeouts on every network call, (c) stopping heartbeats after the limit so the lease lapses and fencing rejects any late commit. | Correctness over forced thread termination. | R10, R12 tests. |
| D-09 | The `assure-flow` Switch agent is the deterministic integration identity: it consumes all events and posts all workflow messages. LLM agents (Claude Code via Switch Console) are optional and may only use the read/request tools; they can never confirm, decide or approve. | "AI reads and explains; code validates; people decide." | T05; `POST /review-requests/{id}/decisions` returns 403 for every agent. |
| D-10 | Extraction provider defaults to `fake` (replays recorded fixtures by SHA-256) so a clone runs with no API key; `LLM_PROVIDER=anthropic` uses Claude (`claude-opus-5-5`) vision with JSON-schema-constrained output via `messages.parse`. A model refusal is treated as a permanent extraction failure (case held, owner asked for a better copy). | Offline CI must not touch a live model (G-15). | T01/T02 offline; live extraction needs a key. |
| D-11 | When a material field is missing, confirmation requires either a typed value or an explicit `hold` (`ok INV-0001 hold`); held fields then surface as owner-routed `needs_evidence` issues. | Spec: "every material field has a value or an explicit hold". | Owner-gap test. |
| D-12 | Seed data lives in one file, `seed/practice.yaml` (practice, shops, users), plus `agents/rooms.yaml`. | Smaller surface for the same content. | None. |
| D-13 | `requirements.lock` is a pinned `pip freeze` of runtime packages (no uv/pip-tools available). | Reproducible installs. | Docker build. |
| D-15 | Live run used the deployment's bootstrap registration key (spec-compatible: agents registered with it belong to a dedicated non-admin account). Consequence: the agent cannot change its own addressing (`update_agent_detail` → 403, owner-only), so Switch's default "owner only" addressing applies to @mentions. Workflow events never need a mention, so nothing depends on it. | Switch 0.31.0 identity model. | None for workflow; an @mention from a person gets Switch's refusal. |
| D-16 | Rooms are created by the `assure-flow` agent itself (`create_room` op, default bridge) from `agents/rooms.yaml` (`scripts.admin create-rooms`). Switch's standalone deployment also adds its admin accounts to each room; the outbox audience check uses the declared `room_members`, not Switch's live member list. | Reproducible setup; a live member-list check is future work. | Recorded in README limitations. |
| D-14 | Fixtures print per-component rates (CGST%/SGST%/IGST%). The legacy generator printed only a combined "Tax %", which the arithmetic contract correctly treats as `needs_evidence`; F14 keeps one combined-rate document to prove that path. | Arithmetic contract (s.5). | Golden fixtures. |
